🏗️架构设计

多模型结果级融合（不同组合：精度专家 + 快路径 + 微调族），sequence_expert 路由（按序列 ID 选择最优方法）或加权投票。fusion_6way 系列引入 v4 微调族与 ep7。

🔬技术细节

**融合范式**：结果级（late fusion）——各 tracker 独立跑完全序列输出逐帧 bbox，融合层按策略选框，不共享中间特征。**两种路由策略**：①`sequence_expert`：按序列 ID 固定选择该序列在验证集上的最优方法（oracle 式，训练集泄漏风险——测试集序列 ID 未知，实际部署不可用）；②加权投票/均值：多模型 bbox 按置信度加权。**组合方式**（eval_fusion.py）：2way（sutrack_b224+lorat 类）、3way（精度+快路径+微调）、4way/5way（fusion_5way = 精度专家×2 + 快路径×2 + 微调）、6way（5way+v4 微调族）、8way（全组合）；v1v4/ep7 变体替换微调族来源。**关键实证**：fusion_5way AUC 0.522 > 单模型最好 0.4919（+3.0 点），但 oracle 上限 0.5779（逐序列选最优）——简单融合只捕获了多样性收益的一小半；FPS 多为 nan（并发评测未 solo 复测）。**两组件 oracle 对**（component_diagnostics）：fusion_3way+fusion_6way_v4 0.552、fusion_6way_v4+lorat 0.551、lorat+sutrack_b224 0.547——含 lorat 的对精度最高，印证其专家价值。

🧠机理分析：为什么在长处场景有效

**为什么融合有效（+3 点）**（结构归因）：不同 tracker 的失效模式互补——ODTrack 系（dense memory）在长时稳定序列强、SUTrack（自回归）在 sim 域强、LoRAT（DINOv2）在 real 域强、UETrack（轻量）在简单帧快——结果级融合取『多数一致/高置信』时天然压制单一模型的系统性偏差（如 ODTrack 的失锁污染、LightFC 的外观漂移）。**为什么只到 0.522（距 oracle 0.5779 差 5.6 点）**：①**融合在错误方向上也融合**——加权投票无法识别『哪个模型此刻是对的』，只会平均；②**sequence_expert 的 oracle 上界**——按序列 ID 选最优是事后最优（含泄漏），真实部署没有序列 ID 先验，动态路由（置信度/状态）才能逼近；③**模型相关性**——同族变体（ft_ep6/7/8）高度相关，融合增益递减（fusion_8way 0.490 反而不如 5way 0.522）。**为什么含 lorat 的对精度最高（oracle 对 0.547-0.552）**：LoRAT 的 DINOv2 特征与其它模型（CNN/轻量 transformer）差异最大——多样性（模型异质性）是融合收益的来源，同构模型融合无增量。**部署意义**：融合的 +3 点是『零训练』的保底增益，但 0.8 目标需要动态路由（adaptive_spherical）而非静态组合。

⚖️优缺点

优点

  • 全部组合超过单模型最好（0.4919→0.522）
  • 简单投票/专家路由即可稳定 +3 个点
  • 『按序列选最优』的 oracle 验证了多样性的存在（0.5779）

缺点

  • 融合增益天花板明显：0.522 离 0.5779 oracle 还有 5.6 个点
  • sequence_expert 依赖序列 ID（训练集泄漏风险，测试集不可用）
  • FPS 多为 nan/并发观测，速度未验证
  • 离提交目标 0.8 差距巨大——组合已知方法填不平

🎯适用场景

低风险增益项：融合作为提交方案的保底提升（+3 点）；但按序列 ID 路由不可用于隐藏测试集，必须换成置信度/状态驱动的动态路由。
