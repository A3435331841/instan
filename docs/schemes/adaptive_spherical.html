🏗️架构设计

NORMAL（主干快跟踪）→ 球面运动证据触发 SUSPECT → 连续低置信 LOST → 稀疏专家（B224 等）按状态片段调用（非孤立探测）→ VERIFY（anchor 相似 + 运动合理 + 分数门槛）→ 恢复或保持 LOST。专家预算由实测 33.3ms 帧目标计算，延迟自适应调节调用率。

🔬技术细节

**四态状态机**（AdaptiveSphericalTracker，`AdaptiveStatus`）：NORMAL → SUSPECT（quality < suspect_quality 或运动异常/anchor 相似度低，连续 suspect_run 帧）→ LOST（quality < lost_quality 连续 lost_run 帧）→ VERIFY（专家候选通过 _verify_candidate）→ NORMAL（连续 verify_frames 帧 quality ≥ recover_quality）。**证据函数**（_evidence）：融合主跟踪器 quality、响应熵、anchor 相似度（_anchor_similarity）、球面运动一致性（_angular_distance + SphericalState 更新）、尺度变化，产出 policy_score 驱动 LinearRiskPolicy。**专家预算**（ExpertBudget）：由实测帧目标 33.3ms（30 FPS）与主/专家延迟 EMA（_update_latency_budget，latency_ema_alpha 平滑）计算 call_fraction 与专家 token 预算——保证专家调用不突破实时预算。**状态化专家片段**（expert_episode_remaining）：专家一旦被接受就连续运行 expert_episode_frames 帧（短状态片段），而非每帧孤立探测——避免每次重置慢专家的初始化开销（v1 教训：孤立探测导致 20% 额外 B224 开销却只复现 T224 结果）。**恢复判据**：expert_better（专家 quality ≥ 主 × 系数）或 recovery_vote（主 quality < lost_quality 且专家 ≥ expert_quality），且两路框 agreement < disagreement_iou 才切换。**trace 输出**：逐帧 trace.jsonl（route_reasons/expert_used/latency_ms/各子延迟），latency.json 汇总。

🧠机理分析：为什么在长处场景有效

**为什么这是通往 0.8 的最现实路线**（结构性论证）：简单融合只做『结果级组合』（0.52），而 adaptive 在**系统级**引入三个文献级缺口的解法——①**判丢**：球面运动证据（_angular_distance + SphericalState）是全景域特有的强判丢信号（目标在球面上运动有几何一致性，异常即可疑），比 recapture 的 NCC 代理信号更本质；②**找回**：状态化专家片段（episode）避免『每次探测都重置慢专家』——v1 失败（孤立探测多付 20% 开销）证明『如何调用专家』与『选哪个专家』同等重要；③**预算**：ExpertBudget 用实测帧目标（33.3ms）+ 延迟 EMA 动态调专家调用率，把『自适应』从启发式变成闭环控制。**为什么 v1 micro gate 未过（复现 T224 却多付 20% 探测）**：B224 专家与 T224 主干精度差仅 3 点（0.4919 vs 0.4614），在 80 帧窗口内专家几乎没有机会展示优势，而每次探测都付 B224 的初始化延迟——**专家选择空间不足**是 v1 失效的机理（要换更分化的专家如 lorat/SAM2，或只在 LOST 后调用）。**为什么 trace 是它的杀手锏**：trace.jsonl 把每帧的路由原因/子延迟落盘，使『调参』变成『数据驱动的归因』（主干 P95 28ms vs 专家 58ms 是 v2 设计的直接依据）。

⚖️优缺点

优点

  • 四态状态机 + 球面运动证据 = 全景域正确的自研方向
  • 状态化专家片段（episode）优于孤立探测（避免每次重置慢专家）
  • trace.jsonl / latency 输出使瓶颈可测量（主干 P95 28ms）
  • sparse expert token 预算有实测帧目标支撑

缺点

  • v1 复现 T224 结果却多付 20% 探测开销——路由收益未兑现
  • micro gate 样本太小（80 帧 1 序列），不代表全量
  • 专家选择（B224）与主干（T224）差距仅 3 个点，路由收益空间有限
  • 全序列 episode 验证仍在排队

🎯适用场景

通往 0.8 目标的最现实技术路线（架构级增量而非组合已知方法）；需全序列验证 + 更优专家组合（lorat 真实场景专家等）。
