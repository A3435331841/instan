LightFC ONNX（轻量全帧跟踪器）

LightFC（特征关联轻量跟踪器）经 ONNX 双子图接入全帧路线。代表序列 AUC 0.618 一度为推荐方案，120 序列全量评测仅 0.3116——小样本数字的典型教训。

🏗️架构设计

LightFC 双子图 ONNX（backbone 2.2MB + tracking 12.7MB），ERP 全帧输入，搜索区水平回绕，对齐 BaseTracker 契约。

🔬技术细节

**LightFC（轻量特征关联跟踪器）**：以轻量卷积 backbone（MobileNet 类）提取特征，用逐层关联（correlation）取代 transformer 的全局注意力，在保持特征交互能力的同时大幅压缩计算量。**ONNX 双子图拆分**：①backbone 子图（2.2MB）——对模板/搜索帧提取特征；②tracking 子图（12.7MB）——特征关联 + 头回归。拆分使模板特征可复用（首帧提取一次）。**接入方式**：对齐 BaseTracker 契约（init/update），输入 ERP 全帧，搜索区裁剪水平回绕处理 360° 跨界；全帧跟踪器在 eval_360vot.py 走 _eval_full_frame 直连路径（不经 BFoV 切图与全局重检测）。**性能**：纯模型推理 38 FPS，端到端 CPU ~10 FPS——4K JPEG 解码是主要瓶颈。**配置**：search_size=256, search_factor=4.0, template_size=128, template_factor=2.0, hp_sigma=0.0（Raw 输入，复用 Direct ERP 的 highpass 损害结论）。**历史教训**：3 代表序列全帧 AUC 0.618/SR 0.749（先进水平）→ 120 序列全量仅 0.3116，小样本数字严重高估。

🧠机理分析：为什么在长处场景有效

**为什么代表序列强（AUC 0.618）**：LightFC 的逐层特征关联（correlation）在目标外观稳定、尺寸适中的序列上表现优异——轻量 backbone 已能提取足够判别特征，且 3 条代表序列（0008/0036/0116）恰好是这种『温和』场景，150 帧短序列内目标外观变化有限。**为什么全量崩盘（0.3116）**（结构性归因）：①**无时序记忆**——LightFC 是单帧匹配器（每帧独立关联），不做跨帧状态累积，长时序列（2400 帧）中外观漂移后无法自校正；②**无判丢/重捕获**——一旦关联错误（相似物、遮挡）就永久跟错，与 ODTrack 的 dense temporal memory 形成鲜明对比；③**轻量骨干的容量上限**——MobileNet 类特征在困难外观（强形变/相似物）下判别力不足。**为什么 CPU 实时**：双子图 ONNX + 关联计算的算力需求远低于 transformer 全局注意力，backbone 2.2MB 的特征提取开销极小。**教训的机理**：代表序列 0.618 是全量 0.3116 的 2 倍——小样本的『场景选择性』放大了方案在温和场景的真实能力，这正是项目确立『全量评测纪律』的技术根因。

⚖️优缺点

优点

  • 模型极小（~15MB），CPU 实时（~10 FPS）
  • 代表序列表现先进（AUC 0.618 / SR 0.749）
  • 轻量线生产仅依赖 numpy/Pillow/scipy + onnxruntime，无 torch/cv2

缺点

  • 120 序列全量只有 0.3116，小样本数字严重高估
  • 对困难序列（长时/遮挡/小目标）泛化差
  • 双子图 ONNX 导出与版本管理成本

🎯适用场景

轻量/低算力场景或融合中的 Scout 分支；不作为精度主干。
