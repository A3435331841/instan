Direct ERP + VitTrack（全帧直连）

绕过 BFoV 切图，直接在全帧 ERP 上跑 VitTrack。精度与 BFoV 持平但速度提升 20 倍、彻底消除漂移——是『全帧直连』路线的首个证据。

🏗️架构设计

ERP 全帧直喂 VitTrack（onnxruntime 双子图或 cv2），仅处理 360° 边界 x 回绕。无状态预测、无切图、无坐标转换。

🔬技术细节

**输入表示**：全帧 ERP (H,W,3) 直接送入 VitTrack，无 BFoV 切图。目标在 ERP 坐标 (x,y,w,h) 下直接跟踪，搜索区域即整幅全景（VitTrack 内部以模板为中心的注意力天然覆盖全帧）。**边界回绕**：update() 中预测框 x<0 时 +=W，x≥W 时 -=W，最终 x 钳制到 [0,W-w)——处理 360° 经度环绕。**推理后端**：onnxruntime 双子图（backbone 提取模板/搜索特征 → tracking head 回归），无 cv2 依赖；旧 cv2.TrackerVit 仅作本地验证 fallback。**预处理消融**（关键实证）：Raw ERP 帧最优（AUC 0.263, FPS 159）；highpass σ=3 降至 0.082（移除低频上下文信息，严重损害）；σ=5 为 0.094。**多尺度消融**：单尺度最优（0.263, 172 FPS）；0.5x 金字塔略降（0.261, 93 FPS）——VitTrack 内置 sr_ratio 已处理多尺度搜索，外部金字塔无益。**配置**：tracker=direct_erp, model_path=object_tracking_vittrack_2023sep.onnx。

🧠机理分析：为什么在长处场景有效

**为什么消除漂移**（结构对比）：BFoV 方案是『预测中心 → 切图 → 局部匹配』的开环链路，预测误差沿时间累积；Direct ERP 是『全帧输入 → 全局匹配』的闭环——VitTrack 的注意力天然覆盖整幅全景，目标出现在任何经度都能被搜索到，不存在『预测中心偏离』这一失效模式。**为什么 Raw ERP 优于 highpass**（预处理归因）：highpass 滤除低频分量，而 ERP 全景的低频信息（大面积天空/地面/场景布局）恰是目标定位的全局上下文；VitTrack 的 patch embedding 需要完整频谱建模目标与环境的关系，滤波后特征判别力骤降（AUC 0.26→0.08）。**为什么多尺度金字塔无益**：VitTrack 内部 sr_ratio 机制已在特征空间内做多尺度搜索，外部像素级金字塔是冗余且引入额外插值噪声。**为什么速度快 20 倍**：省去切图投影、状态预测、坐标转换三处每帧计算 + 省去小图重采样，只做一次全帧前向与一次 x 回绕。**局限的机理**：精度仅 0.26 是因为 VitTrack 本身能力上限（无时序记忆、无重捕获），Direct ERP 只是『最大化单帧匹配』，无法积累时序信息——这解释了为何它被有 dense temporal memory 的 ODTrack 超越（0.26→0.58）。

⚖️优缺点

优点

  • 消除框架漂移（无状态预测累积误差）
  • 速度 20 倍于 BFoV（155 vs 8 FPS）
  • 实现简单：仅 x 坐标模 W 回绕
  • Raw ERP 帧最优（highpass 损害 AUC 0.26→0.08；多尺度金字塔无益）

缺点

  • 全帧 4K 输入内存/带宽开销大（被 ODTrack 三平铺的降采样解决）
  • 精度仍只有 0.26 量级（VitTrack 自身能力上限）
  • 生产路径需要 ONNX 双模型（backbone + tracking）

🎯适用场景

验证了全帧直连的可行性；速度-精度权衡的基准。后被 ODTrack 三平铺超越（0.26→0.58）。
