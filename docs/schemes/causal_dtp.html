Causal-DTP-ERP（教师-学生路由）

教师（ODTrack 三平铺）+ 学生（UETrack ERP-wrap）+ Scout（LightFC）三模型，Scout 判定难度后决定是否调用教师。当前保守路由保护 ODTrack 精度（AUC 与 ODTrack 相同 0.5792），未带来增量。

🏗️架构设计

Scout（LightFC）低开销预判 → 难度路由：简单帧走学生（UETrack 快路径），难帧调教师（ODTrack 精度）。意图是降低教师调用率换速度，同时保精度。

🔬技术细节

**教师-学生-侦察三模型路由**：教师=ODTrack ERP 三平铺（AUC 0.5792 精度锚点），学生=UETrack ERP-wrap（57 FPS 快路径），Scout=LightFC ONNX（CPU 可跑的低开销预判器）。**路由策略**：Scout 逐帧输出置信度/难度信号 → 低于阈值的帧调用学生（快路径），高于阈值（疑似困难/失锁）才调用教师（精度路径）。**实现**（scripts/fuse_causal_dtp_erp.py）：`fuse_sequence` 按帧融合两路输出，`circular_blend_box` 做跨界框的循环融合（经度环绕语义下的框混合），`fuse_geometry_experts` 融合几何专家。**当前状态**：保守路由——Scout 判难不充分时全部回退教师，结果 AUC/SR/FPS 与纯 ODTrack 完全一致（0.5792/0.6532/8.99），即路由未带来任何增量。**设计意图**：先保精度（教师全调），后续训练学生模型后逐步降低教师调用率，兑现速度收益。

🧠机理分析：为什么在长处场景有效

**为什么思路对但没兑现**（结构性归因）：难度感知路由的前提是『Scout 能可靠区分简单/困难帧』——但 LightFC 作为 Scout 的判难信号（其置信度/响应）与真实难度（ODTrack 是否会失锁）相关性未经标定，保守路由直接回退教师，导致 100% 教师调用。**为什么保守路由 AUC 与 ODTrack 完全相同**：代码路径上简单帧也走教师（Scout 判难阈值保守），等于没有路由——0.5792/0.6532/8.99 三个数字与 ODTrack 逐位一致，是『路由未生效』的直接证据。**什么条件下会有效**：①Scout 换成与教师失锁模式强相关的信号（如 anchor 相似度、运动一致性——recapture 已证明这些离线信号有区分度 0.747）；②学生模型训练完成（知识蒸馏让 UETrack 逼近 ODTrack 精度），简单帧用学生不掉点；③路由阈值用 60/60 留出标定而非启发式。**与 adaptive_spherical 的关系**：Causal-DTP 是『帧级二元路由』（简单/困难），adaptive 是『四态状态机 + 稀疏专家』——后者是前者的超集，这也是 Causal-DTP 被降级为叙事的原因。

⚖️优缺点

优点

  • 思路正确：难度感知路由是融合的正确方向
  • 教师-学生蒸馏路线为后续留了伏笔（学生模型训练后减少教师调用）
  • 与 Phase 2 专家路由/反事实路由同源

缺点

  • 保守路由=教师全调，无速度收益（8.99 FPS 未变）
  • Scout 判难度能力未经严格验证
  • 结果级路由增益有限（报告中明确『留作叙事』）

🎯适用场景

创新实验版：验证了路由框架可行性；需真实学生模型 + 可靠 Scout 才能兑现速度收益。
