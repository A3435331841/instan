ODTrack + Recapture 外挂（判丢 + 球面重捕获）

给 ODTrack 装『判丢 + 全图找回』外挂：ReliabilityGate（多信号融合判丢）+ TemplateMemory + 多切平面重检测。针对 10 条失锁序列设计，目标是救回一半（+0.02~0.04），但 representative 实测 AUC 0.3981 被 drop。

🏗️架构设计

OdtrackRecaptureTracker（BaseTracker 契约）：ODTrack 逐帧 + ReliabilityGate（C_visual/anchor/motion/scale/geometry 五信号，多信号融合防自信错跟）+ TemplateMemory（门控写入，anchor 永不被覆盖）+ SphericalMultiViewRedetector（redetect_v3，12 视角×3 尺度多模板池）→ LOST 后每 K=5 帧搜索 → VERIFY（分数+anchor 一致性+运动合理）→ REINIT（清空污染记忆）。

🔬技术细节

**判丢公式**（`_reliability`，线性 logit + sigmoid，权重来自离线 60/60 标定）：`logit = w_motion·(C_motion−0.5) + w_scale·(C_scale−0.5) + w_ncc·(C_anchor−0.5) − w_geom·geometry_risk`，`R = 1/(1+e^{−logit})`。四信号：C_motion=预测中心与圆周恒速外推的球面距离归一化；C_scale=框面积 log 变化 vs EMA；C_anchor=预测框 crop 与 anchor 模板的 NCC（归一化 (sim+1)/2）；geometry_risk=极区 |lat|>55° 或 seam 距离 <12%W 的风险项。C_visual（last_pred_iou）实测 Pearson +0.391、判丢区分度 0.747，但因服务器不可用仅有 10 序列证据，权重置 0。**VERIFY 三门槛**：①NCC score ≥ recapture_min_score（0.45）；②候选 crop 与 anchor 归一化相似度 (sim+1)/2 ≥ 0.5（防锁错相似目标；注意原始 NCC 阈值无意义——4K 正常帧原始 NCC 均值仅 ~0.22）；③候选中心与失锁前位置的球面角距离 ≤ motion_max_deg（90°）。**多视角重检测**（redetect_v3 `search`）：6-8 个经度切平面视角（view_centers）→ 每视角 ERP 窗口降采样 2× → highpass 灰度 → 对模板池（anchor + 高可靠短/长记忆）逐尺度（template_scales）算 NCC 响应场 → 亚像素峰值（_subpixel_peak）→ 局部像素映射回 ERP（x 回绕）。**REINIT**：用候选框重新 tracker.initialize（三平铺帧 + 框居中），彻底清空被污染的 dense temporal memory，再 OBSERVE 3 帧防立即失锁。

🧠机理分析：为什么在长处场景有效

**为什么方向正确但实测 drop（0.3981）**（结构性归因）：①**重检测器能力不足**——redetect_v3 的全局搜索用 NCC 在 6-8 个切平面视角做模板匹配，但 4K 全景上 NCC 对『外观变化后的目标』召回率低（recapture 的 VERIFY 门槛严格，宁可 LOST）；NCC 模板匹配在失锁场景的失败模式与 NCC 基线同源——外观变化使相关性衰减。②**判丢信号权重证据有限**——C_visual（last_pred_iou）只有 10 序列证据权重置 0，离线代理信号（motion/scale/anchor）在真实失锁瞬间（快速移动、遮挡）易误判，导致过早/过晚进入 LOST。③**每 K=5 帧搜索的预算**——CPU NCC 全局搜索每次 <2s，但失锁期间目标可能已离开所有切平面视角的覆盖（极区/快速横穿）。**为什么这个失败仍有价值**：它证明『判丢+重捕获』的架构思路是对的（360VOT Issue #11 也支持多切平面），失败的是 NCC 这个重检测器——经验直接沉淀进 adaptive_spherical（四态状态机 + 球面运动证据 + 专家预算），并把重检测升级为『稀疏专家探测』而非全图 NCC。**对比**：representative 0.3981 比纯 ODTrack 基线低 20 个点——外挂的误锁/漏找回代价大于救回收益，验证了『宁可不做不可做错』的工程判断。

⚖️优缺点

优点

  • 方案设计完整：判丢多信号融合（单信号有反例 0004）、VERIFY 防误锁、REINIT 防记忆污染
  • last_pred_iou 相关性实测（Pearson +0.391，判丢区分度 0.747）支持信号方向
  • 『宁可继续 LOST 不可锁错』的诚实边界与 60/60 留出标定纪律
  • 多切平面重检测（禁直接喂整张 ERP）有 360VOT Issue #11 文献证据

缺点

  • representative 实测 0.3981 大幅低于 ODTrack 基线（0.59 量级）——外挂净收益为负
  • 重捕获 CPU NCC 开销拖慢 FPS（23 vs 纯 ODTrack 29.9）
  • server 不可用时置信度信号改用离线代理，标定证据有限
  • VERIFY 双模板一致性 v1 未实现，防误锁能力打折

🎯适用场景

失败（drop）。方向正确但实现/标定不成熟：recapture 需要更准的判丢信号与更强的重检测器（如 YOLO-World/SAM2），单纯 NCC 重检测在 4K 全景上召回不足。
