# 360VOS 微调方案评估(2026-08-03)

## 一、现状(已验证数据)

| 项 | 结果 |
|---|---|
| LightFC 预训练权重 | ✅ 已下载并验证加载(ep0400, MobileNetV2 主干) |
| LightFC CPU 推理封装 | ✅ 已通过单帧验证,5 序列 AUC 0.44~0.80 |
| 本机硬件 | ❌ 无 GPU、无训练能力(仅 CPU,可跑推理) |
| 360VOS 训练集 | HF 仓库 `train/001.zip ~ 170.zip`,共 170 序列,**约 56 GB** |
| 训练集格式 | 与测试集同为 zip(image + mask + label.json) |

## 二、为什么微调能到先进水平

- 360VOTS 论文实测:LoRAT 在 360VOT 上仅微调 **10 epoch** 就 +7.4% S_dual(0.42→0.495);
- 360VOT 测试集与 360VOS 训练集同源同分布,微调是"对症下药";
- LightFC 是 3.2M 轻量模型,微调数据量小(170 序列 vs 论文原始训练集数千序列),收敛快。

## 三、数据准备方案(本机可做,约 6~7 小时下载)

1. 下载训练集(可复用现有下载脚本,前缀 `train/`):
   ```bash
   python scripts/download_all_360vot.py   # 需要改前缀为 train/、编号 3 位(001~170)
   ```
   或按需下载子集(如先下 30~50 序列做验证性微调,约 15~20 GB)。
2. 解压:zip 内为 `<seq>/image/ + <seq>/mask/ + <seq>/label.json`(与测试集结构一致)。
3. **数据泄漏检查**:360VOS 训练集与 360VOT 测试集有 **99 条重叠序列**,微调前必须按序列 ID 剔除重叠,否则本地成绩虚高(策略文档已注明)。下载后需对照 `360vots-info.csv` 的 360VOS ID 做去重。

## 四、GPU 训练策略(需租云 GPU,学生预算内)

| 方案 | 硬件 | 成本 | 时间 |
|---|---|---|---|
| **推荐** | 租 RTX 3090/4090(24G) | 约 ¥2~5/小时 | 微调 1~2 天,总花费 <¥200 |
| 备选 | 租 A5000/A6000 | 略贵 | 更快 |

微调流程:
1. 在云 GPU 机器 clone LightFC 官方仓库 + 放训练数据;
2. 按官方 train.py 配置,`load_state_dict` 载入 ep0400 权重后继续训练(不是从零训);
3. 训练集 = 360VOS 去重后子集,小 batch、低学习率(如 1e-4)、10~50 epoch;
4. 微调后导出 ONNX(官方有 `PreprocessorX_onnx` 参考),塞进你们现有 Docker 管线。

## 五、风险与备注

- **与 360VOT 测试集重叠的去重是硬门槛**,漏做会导致本地分虚高、答辩穿帮;
- 微调需 torch GPU 环境,与本机 CPU 环境分离,建议用独立 conda/venv;
- 微调完的 ONNX 推理端仍可用本机 CPU 验证(8 FPS 已实测);
- 若时间紧,可先不微调直接提交(预训练 LightFC 已能到 0.44~0.80 量级),微调作为加分项。

## 六、结论

**可行且性价比极高**:下载训练集(6~7h)→ 租 3090 微调(1~2 天,<¥200)→ 导出 ONNX 部署。预计微调后 5 个代表序列 AUC 可再提升 5~10 个百分点,达到"先进水平(0.5+)"。
